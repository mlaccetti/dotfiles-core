Mac setup guide

Claude Workstation Setup

When you finish, you will have a terminal where you type a plain-English request and Claude Code does the work across Linear, Confluence and Jira, and GitHub. It can also build small web apps, following the documentation you keep in Confluence.

Plan on 30 to 60 minutes of hands-on time. Your ticks are saved in this browser, so you can close the page and come back.

What setup installs

Setup installs these if they are missing and skips any you already have. You do not need any of them before you start.

Installed if missing

  • iTerm2
  • Visual Studio Code
  • Claude Code
  • 1Password
  • The 1Password command line tool (op)
  • Slack

Then setup adds

  • The fonts
  • The terminal theme and the prompt
  • The command-line tools Claude Code uses
  • Node
  • claude-gw, for an LLM gateway if you use one
  • The connections to Linear, Atlassian and GitHub

What you will be able to ask

After setup, you type requests like these into Claude Code and it does the work.

  • LinearSummarize the open Linear issues in my team's current cycle.
  • ConfluenceDraft a Confluence page from these meeting notes.
  • Web appBuild a small dashboard for this week's signups, following the deployment steps on the Deploying page in Confluence.

How to use this page

The terminal is an app where you type commands instead of clicking buttons. Typing a command does exactly what it says and nothing more.

  • A dark box is a command. Click Copy, click into the terminal, paste with Cmd+V, then press Return.
  • Use Terminal for Steps 1 to 3. Setup installs iTerm2 if you do not have it. From Step 4 on, open iTerm2 and run every command there.
  • Text scrolls past while a command runs. You only need to read it if it says FAIL or an error.
  • If a command finishes and gives you your prompt back with no error, it worked. Silence is success.
  • Every step is safe to run again. If one fails, fix that one thing and repeat it. You do not need to start over.

The steps

Tick each box as you finish. Do them in order, because each one builds on the last.

1

Check that Homebrew works

Homebrew is the tool that installs everything else in this guide. Open Terminal (or iTerm2, if you already have it) and check whether Homebrew is installed:

brew --version

You should see

A line that starts with Homebrew and a version number. Any extra lines after it are fine. If you see that, tick this step and go on to Step 2.

If it fails

If you see "command not found", Homebrew is not installed yet. Install it with the commands below.

Only if Homebrew is missing

Run the official installer. It may ask for your password, and it takes several minutes. It also installs Apple's command line tools if they are missing, which can show a macOS dialog: click Install.

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

When it finishes, make Homebrew available in this window. This prints nothing:

if [ -d "/opt/homebrew" ]; then
  eval "$(/opt/homebrew/bin/brew shellenv)"
else
  eval "$(/usr/local/bin/brew shellenv)"
fi

Then run brew --version again. This only affects the current window. After Step 3, your settings put Homebrew on your path in every new window.

If your Mac restricts installing software, this install is the one most likely to be blocked. If it fails or waits for permissions you do not have, ask whoever manages your Mac to approve Homebrew or install it for you, then come back to this step.

2

Install chezmoi

chezmoi downloads the settings from the repository and runs the install steps in the right order.

brew install chezmoi

You should see

Homebrew downloads and installs chezmoi, ending with something like "chezmoi was successfully installed."

If it fails

Run brew doctor and follow what it recommends, then try again. If Homebrew itself is not working, go back to Step 1.

3

Run the main setup

This is the big one. It asks three short questions, then installs whatever is missing, including the FiraCode Nerd Font that draws the icons and arrows in your prompt. It applies all the settings and the Claude Code theme, and installs two small commands, claude-gw-setup and claude-gw, which you only need in Step 7 if you use an LLM gateway. It leaves any app you already have as it is. It takes a while, and the installs are the slowest part.

chezmoi init --apply https://github.com/mlaccetti/dotfiles-core

Partway through, setup prints a short list of anything it found already installed and left alone. It starts with Already installed, leaving as is. That is expected, and nothing is wrong.

You will be asked three questions in this exact order. The question text below is what the terminal prints.

Your full name (used for git commit authorship)
TypeYour own name, as you would sign an email.
Your email address (used for git commit authorship)
TypeYour email address.
Do you use 1Password and want this setup to read secrets from it? Type true or false - if unsure, type false (you can turn this on later)
Typefalseunless you already use the 1Password command line tool and want setup to read secrets from it. You can change this later by running the command again. Either way, setup installs the 1Password app and its command line tool if they are missing, and leaves them alone if you have them.

You should see

After the three answers, a long stream of output. Homebrew installs whatever is missing (several minutes), your settings are written, and there are notes about the iTerm2 profile and the Claude Code theme. A message about ~/.oh-my-zsh is safe to ignore on a new machine.

If it fails

  • If one Homebrew package fails partway, your Mac may be restricting installs. Setup keeps going. Write down which one failed and get it approved, or ignore it for now. The health check in Step 9 lists what is still missing.
  • You can run this command again at any time. It asks the three questions again and does not damage your files.

Check your git identity afterward

Your name and email are saved to your git settings only if none were set already. If your Mac already has a git identity, setup will not overwrite it. When it finishes, check what you ended up with:

git config --global user.name
git config --global user.email

If either is wrong, set it with git config --global user.name "Your Name" or git config --global user.email "you@example.com".

4

Restart the terminal

Step 3 changed your shell settings. Open a brand-new terminal window (an old tab keeps its old settings). From here on, use iTerm2, which setup installed if it was missing. Or run this in your current window:

exec zsh -l

You should see

Your prompt comes back with colored segments and git branch information, in place of the plain default prompt. Compare it to the preview at the top of this page.

If it fails

If the new prompt does not appear, check that you opened a new window. If a command like bat, fzf or chezmoi says "command not found", open a new window or run exec zsh -l again.

5

Set the iTerm2 look

Setup can only make the "Anthropic" profile the default when iTerm2 is closed while it runs. Do it yourself now, in iTerm2. There is no command for it, so it is a few menu clicks:

Set the Anthropic profile as the default

iTerm2 > Settings > Profiles > Anthropic > Other Actions (gear) > Set as Default

  • In iTerm2, open Settings from the iTerm2 menu, then click Profiles. Older versions call it Preferences.
  • Click Anthropic in the list on the left.
  • Click the small gear icon (Other Actions) under the list and choose Set as Default.
  • Open a new window. New windows use the new default. Compare it to the preview at the top of the page.

If it fails

If "Anthropic" is not in the list at all, see Troubleshooting.

If your new window already matches the preview, setup set the default for you. Tick this step and move on.

6

Check that Claude Code is signed in

Setup installed Claude Code if it was missing. If claude already opens without asking you to sign in, and /status shows your account, you are already signed in and can skip this step. Otherwise, sign in with the account you use for Claude. You do this once, and after that plain claude uses it every time. Do this in your new iTerm2 window.

claude

The first time you run it

If setup installed Claude Code, macOS may show a dialog saying it cannot verify the app. That is normal for software installed outside the App Store, and nothing is wrong. Click Open or Open Anyway. If the dialog has no such button, open System Settings > Privacy & Security, scroll down, and click Open Anyway next to the message about claude. This happens once per computer. If claude seems to hang with no output, the dialog is probably hidden behind another window.

You should see

If you are not signed in, Claude Code asks how you want to log in.

  • Choose the Claude account option (the one that mentions Pro, Max, Team, or Enterprise). Do not choose the Console or API key option.
  • A browser window opens. Sign in with the account you use for Claude. If it uses single sign-on (SSO), you may land on that account's normal login page.
  • Go back to the terminal. Answer any other first-time questions, like the color theme or trusting the folder, with the suggested default.

Once you see the Claude Code prompt, you are signed in. Type /exit to leave for now.

When Claude Code asks whether you trust a folder, say yes only for folders you know, such as your own projects or repos from people you trust. A trusted folder can run its own setup scripts, and those scripts can use your saved tokens.

If it fails

  • If claude just sits there with no output, or macOS says it cannot verify the app, see Troubleshooting.
  • If the browser window never opens or the sign-in is blocked, ask whoever manages your Mac whether browser sign-in is allowed for Claude Code.
  • If it says your account has no access, check that your Claude plan includes Claude Code.
  • If you picked the Console option by mistake, type /logout (this is fine in plain claude, and only there), then run claude again and choose the Claude account option.
  • If the command is not recognized, open a new iTerm2 window.
7

Set up an LLM gateway Optional

Skip this step if you do not use an LLM gateway. If you do, you set it up once, and then claude-gw uses it. You need the gateway address and your gateway token from whoever runs your gateway. Ask them for the model names too, if the gateway needs specific ones. Ask for the token through a password manager or another secure channel, not plain chat or email. Have these ready before you run the command.

claude-gw-setup

It asks you four questions:

Gateway address (starts with https://)
TypePaste the address you were given.
Gateway token (typing is hidden)
TypePaste your token. Nothing appears on screen while you paste or type it. That is on purpose, so nobody looking over your shoulder can read it. Press Return when you are done.
Does the gateway need specific model names? (y/N)
Typenunless you were told the gateway uses its own model names. If so, type y and enter the Opus, Sonnet and Haiku names you were given. Press Return to skip one you were not given.
Test the connection now? This sends one tiny request. (Y/n)
TypePress Return, which means yes.

You should see

"The gateway answered", then "All set." Your token is saved in a private file that only your account can read (~/.config/claude-gw/). It is never written into your regular Claude Code settings.

If it fails

  • "command not found": run chezmoi apply to install the commands, then open a new terminal window.
  • "The gateway rejected the token": the token was mistyped or is not valid. Get it again from whoever runs the gateway and run claude-gw-setup again. It is safe to run again at any time.
  • "couldn't reach": check the address, and check that you are on the network or VPN the gateway needs, if any.
  • If Claude Code will not let you use both sign-in methods, a setting such as forceLoginMethod may be locking it to one. Whoever manages your Claude Code settings can change that.

Which one to use: claude or claude-gw

Claude account

Use claude with the account you signed in with in Step 6.

Gateway

Use claude-gw when you want the gateway instead. It takes the same commands but signs in with your saved gateway token, so some Claude.ai features, like apps connected on the Claude website, will not appear there.

To start Claude through the gateway:

claude-gw

Caution

Never type /logout inside claude-gw. It can sign you out of your Claude account, and you would have to sign in again with claude.

If a gateway session shows a warning about a saved login, ignore it and do not log out.

Good to know about the gateway

  • Your Claude sign-in stays saved while you use the gateway. Switching is just typing the other name.
  • Usage is billed to the gateway, not to your Claude plan.
  • Your Linear and Atlassian connections (Step 8) work in both, because they are added with --scope user. Anything connected only through the Claude website appears only in plain claude.
  • Settings that come from your Claude account may not apply. Remote control and voice do not work.
8

Connect your tools

This is the point of the whole setup. Each tool below is connected once and opens a normal browser sign-in with your own login. Claude never sees your password. Type the commands at the normal prompt, not inside Claude, unless a step says otherwise. A browser tab opening is expected. If it is blocked, ask whoever manages your Mac whether browser sign-in is allowed for that tool.

Why the commands say --scope user

It makes each connection available in every folder you open Claude Code in, and in both claude and claude-gw. Without it, Claude Code saves the connection only for the folder you were in when you ran the command, and it seems to disappear everywhere else.

8aLinear

claude mcp add --transport http linear-server --scope user https://mcp.linear.app/mcp

You should see

A confirmation that the server was added. It is not signed in yet. You sign in to it in 8c, after adding Atlassian.

If it fails

If claude is not recognized, open a new terminal window.

8bConfluence and Jira (Atlassian)

This only works once Rovo remote MCP access is turned on for your Atlassian site. If you are not sure it is, ask whoever administers your Atlassian site.

claude mcp add --transport http atlassian --scope user https://mcp.atlassian.com/v2/mcp

You should see

The same as Linear: a confirmation that the server was added. You sign in to it in the next block.

If it fails

An error about access being disabled usually means Rovo or MCP is not turned on for your Atlassian site yet. Ask whoever administers the site to enable it. A sign-in that never finishes is usually browser sign-in being blocked on your Mac.

8cSign in to Linear and Atlassian

Adding a connection does not sign you in to it. Do that once for each, in plain claude, not claude-gw.

claude

Then, inside Claude

  • Type /mcp, choose linear-server, and follow the steps in the browser window that opens to log in to Linear normally. Approve access there.
  • Type /mcp again, choose atlassian, and log in to your Atlassian account the same way.
  • When both show as connected, type /exit.

You should see

/mcp lists Linear and Atlassian as connected.

If it fails

If the browser does not open by itself, copy the web address Claude Code shows and open it yourself. If sign-in is blocked, ask whoever manages your Mac whether browser sign-in is allowed.

8dGitHub

gh auth login

You should see

A question about how to sign in. Choose "Login with a web browser" and follow along. It ends with "Logged in as" and your username.

If it fails

If your GitHub access goes through single sign-on (SSO), you may need to authorize the login for it afterward, on GitHub's own website.

8eConfirm the connections

claude mcp list

You should see

Each server you added (linear-server, atlassian) marked as connected.

If it fails

If one says it needs authentication, run claude, type /mcp, choose that server, and follow the browser sign-in. If one shows an error, repeat its connect step above.

9

Run the health check

This checks everything above in one pass. It is safe to run as often as you like.

bash "$(chezmoi source-path)/bin/doctor.sh"

How to read it

The output has sections, and each line starts with a label:

  • [PASS] means that check is fine.
  • [WARN] is for your information. You can ignore it for now. A few can be expected: apps that were on your Mac before setup, such as iTerm2, Visual Studio Code, 1Password and Claude Code, are reported as present but not managed by Homebrew. That is fine.
  • [FAIL] means something is missing. Each one has a Fix: line with the exact command to run.

It ends with a summary. Partway through you will also see a glyph line that you have to check by eye, described next.

If it fails

Work through the [FAIL] lines from top to bottom and run each Fix line. Run the check again after each fix. If you skipped an app because your Mac blocked its install, a [FAIL] for that app is expected, and you can get it approved later. Each Fix line installs only the one thing that is missing, so it never touches the apps you already have.

The glyph check

Partway through the health check, under "Glyph rendering test", you will see three lines: arrow separators, small icons and emoji. The script cannot judge these for you, so look at them yourself. The shapes below show what to expect. The font itself is installed in Step 3.

Looks right

separators icons emoji

Separators are solid triangles that join one color block to the next, like the segments in your prompt. Icons are small recognizable pictures. Emoji are in color.

Looks wrong

separators icons emoji

Hollow rectangles, or a question mark inside a diamond. People call this a "tofu box". It means the terminal is not using the font that setup installed.

If you see hollow boxes or question marks

  1. Confirm you finished Step 5 and that this window is using the Anthropic profile.
  2. In iTerm2, open Settings > Profiles > Anthropic > Text and check that the font is FiraCode Nerd Font Mono. If it shows something else, set it, then run the health check again.
  3. If it is still wrong, open Font Book, search for "Fira Code", and confirm a style named FiraCodeNFM-Reg (or similar) is there and enabled. If it is missing, install the font again with the command below, then quit and reopen iTerm2.
brew install --cask font-fira-code-nerd-font

Keep going

To start Claude Code, open a terminal in a project folder and type claude. That uses your Claude account. If you set up an LLM gateway in Step 7, type claude-gw to use it instead, and never type /logout inside it. Then try the three requests from the top of this page, in your own words. The health check from Step 9 is always safe to run again, and it points at whatever is actually broken.
